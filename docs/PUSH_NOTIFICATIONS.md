# Lumo: основа для push-уведомлений (пока без доставки)

Эта ветка реализует **только безопасную серверную регистрацию Android FCM-токенов**. Отправки push-уведомлений, Firebase SDK в Android и публичного релиза здесь **нет**. Не обещайте пользователям уведомления до проверки полного пути.

## Готово на сервере

- `POST /api/devices/push` с действующей сессией и телом `{"platform":"android","token":"<FCM token>"}`: проверяет формат, возвращает только `{"registered":true}`, не возвращает токен.
- `DELETE /api/devices/push`: удаляет только регистрацию текущей сессии.
- PostgreSQL таблица `push_devices`: ссылки на `sessions` и `users`, SHA-256 токена для уникальности, исходный FCM token (нужен будущему провайдеру) и даты. Транзакция с блокировкой переводит один FCM token на новую сессию при смене аккаунта. `ON DELETE CASCADE` удаляет запись после выхода.
- Схема создаётся повторяемо в `server/db/schema.sql` и `initDatabase`; health check проверяет таблицу; интеграционные тесты работают с двумя инстансами PostgreSQL.
- API не публикует сырые FCM-токены и не пишет их в логи. Доступ к базе и резервным копиям также должен быть защищён.

## Следующий этап: Firebase и Android

1. Владелец создаёт Firebase-проект и регистрирует Android-приложение с package `app.lumo`. Добавляет конфигурацию через управляемое окружение разработки/сборки, а **секреты серверного Firebase Admin не коммитит и не отправляет через чат**.
2. После согласия пользователя Android запрашивает разрешение на уведомления там, где оно требуется, получает FCM token и вызывает новый API с текущей сессией. При обновлении токена повторяет регистрацию; при отключении уведомлений вызывает DELETE. После выхода из аккаунта сервер удаляет запись автоматически.
3. Серверная доставка должна срабатывать только **после успешной записи нового сообщения**. Извлекайте токены с JOIN на действующую сессию `s.expires_at > now()`; не отправляйте push отправителю или заблокированному пользователю. Для нескольких серверных инстансов потребуется надёжная очередь событий/общий pub-sub.
4. По умолчанию на заблокированном экране показывайте нейтральное «Новое сообщение» без текста/имени; подробности только по явному выбору пользователя.
5. При ошибке или отзыве FCM-токена удаляйте устаревшие записи; ограничивайте количество активных устройств и частоту уведомлений на уровне распределённой инфраструктуры.

## Приёмочные испытания

- После регистрации token привязан к авторизованной сессии; смена пользователя на одном устройстве не оставляет два активных владельца; выход отзывает запись.
- Сервис никогда не раскрывает чужой token; недействующая сессия получает HTTP 401.
- После подключения Firebase: проверка на двух телефонах, в фоне, при закрытом приложении, после выхода и при блокировке пользователя. До этого **push-уведомления не работают**.
