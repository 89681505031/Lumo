# Lumo: план развития по восьми направлениям

Все изменения проходят через pull request и проверки. Пока у Vercel действует лимит публикаций, готовые изменения остаются в GitHub и **не считаются доступными в установленном APK**, пока не пройдут сборку, серверное тестирование и проверку рабочей версии.

## 1. Чаты
- Этап 1 (PR #2): непрочитанные сообщения, закрепление чатов по пользователям и отображение этих данных в Android.
- Этап 2: редактирование и удаление собственных сообщений (server-side права, `edited_at` и `deleted_at`), поиск по переписке, контроль событий между инстансами.
- Готовность: тесты истории, обновления последних сообщений, прав доступа, поведения двух устройств и повторных отправок.

## 2. Уведомления
- Создать проект Firebase по согласованию с владельцем, настроить FCM для Android, хранить токены устройств в PostgreSQL с привязкой к сессии, отзывать при выходе.
- Не показывать содержание сообщений на заблокированном экране без согласия пользователя.
- Фоновую доставку тестировать при выключенном экране, закрытом приложении, отсутствии интернета и после восстановления соединения.
- Нельзя считать готовым до настройки Firebase и проверки на реальных устройствах.

## 3. Медиа
- Использовать приватное объектное хранилище и короткоживущие подписанные URL, ограничить размер/MIME, авторизацию просмотра, лимит загрузки.
- В Android добавить выбор и предпросмотр фото/видео/файлов через системный Photo Picker/SAF, запись голосовых по разрешению микрофона.
- Файлы не хранить в PostgreSQL как Base64 и не делать публичными по угадываемым ссылкам.
- Готовность: тесты неавторизованного доступа, истекших URL и ошибок при слабой сети.

## 4. Аудио- и видеозвонки
- WebRTC, сигнализация вызова и отмены с аутентификацией; TURN/STUN для мобильных сетей, защита от спама звонками.
- Не включать до развёртывания надёжной межинстансной сигнализации и тестирования Android-пермиссий.
- Готовность: двусторонний вызов с двух физических телефонов в разных сетях, корректный отказ/сброс вызова и отзыв доступа к камере/микрофону.

## 5. Группы
- Таблицы `groups`, `group_members`, сообщения групп с проверкой членства на сервере, приглашения и роли администраторов.
- Приватный API: запрещён доступ бывшим участникам к новым сообщениям и несанкционированное повышение прав.
- Готовность: тестирование добавления/исключения участников, выхода, истории и отправки сообщений на разных инстансах.

## 6. Дизайн
- Этап 1 (PR #2): локальная светлая/тёмная тема, бейджи непрочитанных, понятное закрепление.
- Этап 2: аватарки на базе защищённой загрузки медиа, доступность, адаптивные экраны и состояния загрузки/ошибок.
- Готовность: проверка на малых экранах, масштабируемом тексте, тёмной теме и TalkBack.

## 7. Приватность и безопасность
- Этап 1 (PR #2): взаимная блокировка новых сообщений по HTTP и WebSocket; список заблокированных и серверная фильтрация поиска.
- Этап 2: настройки приватности профиля, ограничение запросов/спама, аудит авторизации, безопасное хранение токенов на устройстве.
- **Сейчас Lumo не поддерживает сквозное шифрование**: не заявлять такую защиту до отдельной архитектуры и криптографической проверки.
- Готовность: тесты попыток обхода блокировки и чтения чужой информации.

## 8. Обновления
- Опубликовывать только APK с одной и той же стабильной подписью для последующих обновлений (секреты keystore — только в защищённых GitHub Actions secrets).
- Не путать debug APK с production release: APK с другой подписью Android не позволит установить поверх существующего приложения.
- Добавить явное отображение системной ошибки установки, проверку `versionCode`, привязку релиза к проверенному commit SHA.
- Готовность: обновление существующей установленной версии **без удаления и потери локальных данных** на реальном устройстве.

## Порядок работ и контроль
1. PR #2: основа чатов, блокировки, локальная тема; PostgreSQL- и Android-проверки. Никакого слияния при красных тестах.
2. Затем: API редактирования сообщений и безопасные механизмы обновления.
3. После: Firebase/уведомления и приватное медиа-хранилище (потребуется конфигурация владельца).
4. Далее: группы и межинстансная доставка событий; затем звонки с WebRTC и TURN.
5. Финальный этап каждого релиза: серверные тесты, подписанный APK, проверка на двух Android-устройствах и production smoke test.

Разработка в GitHub и выпуск релиза — отдельные шаги. Не публикуем сырой код вместо проверенной версии.
