# Lumo: безопасные обновления Android

## Почему старая сборка иногда не обновляется

Android позволяет установить новую версию приложения **поверх текущей** лишь при совпадении `applicationId`, совместимой подписи и **более высоком versionCode** (при обычном обновлении). Сейчас CI проекта собирает debug APK. Если каждый GitHub Actions runner создаёт свой debug keystore, APK из разных прогонов подписаны **разными ключами** и Android не сможет обновить один другим. Простое изменение кода `PackageInstaller` не решает несовместимость подписей.

**Нельзя гарантировать обновление текущей установленной debug-сборки без переустановки**, если исходный ключ подписи утерян. Сохраните важные сведения и проверьте подписи до миграции. Для всех *последующих* обновлений используйте постоянный release keystore. Не удаляйте нынешнюю сборку только ради проверки.

## Разовая настройка владельцем

1. Надёжно храните оригинальный release keystore вне GitHub и вне чата, с резервной копией. Не отправляйте приватные ключи, пароли или готовую Base64-строку через чат.
2. В настройках GitHub репозитория добавьте Actions Secrets: `LUMO_KEYSTORE_BASE64` (кодированное Base64 **содержимое** стабильного keystore), `LUMO_KEYSTORE_PASSWORD`, `LUMO_KEY_ALIAS`, `LUMO_KEY_PASSWORD`.
3. Определите SHA-256 **сертификата подписи** этого keystore (не путать с SHA файла APK). В GitHub Actions Variables задайте `LUMO_RELEASE_CERT_SHA256`: 64 шестнадцатеричных символа. Это публичный отпечаток сертификата; CI проверяет совпадение с APK перед выдачей артефакта.
4. Сравните сертификат текущего установленного APK с будущим релизом. При несовпадении **обновление поверх него невозможно** без доступного старого ключа или поддерживаемой схемы смены подписи; обычный новый release APK не поможет.
5. После слияния проверенных PR с `main` вручную запустите `.github/workflows/android-release.yml` с уникальным `version_code` выше текущей установленной версии и всех опубликованных релизов. Не запускайте эту работу для PR-веток.
6. Проверьте в результате Actions, что сборка, сертификат и SHA-256 совпали; извлеките `verified-lumo-release-apk`. Рабочий сервер и база данных должны поддерживать новые API до раздачи APK. Публикация GitHub Release остаётся отдельным шагом и не производится этим workflow.
7. Протестируйте APK на двух устройствах: обновление поверх предыдущей версии той же подписи без удаления аккаунтов или потери локальной очереди; проверка входа, чатов, разрешений и восстановления сети.

Артефакт хранится ограниченное время. Подпись никогда не добавляется в Git. При отсутствии секретов или неверном сертификате workflow завершается ошибкой и **не отдаёт APK**.

## Публикация и версии

- Никогда не распространяйте произвольный CI debug APK как обновление release.
- Не меняйте `applicationId=app.lumo`; используйте монотонно возрастающий `versionCode`.
- Не публикуйте на телефоны новую серверно-зависимую функцию до зелёных CI и успешного production smoke test.
- Приложение может предлагать только проверенный релиз с совместимой подписью. В интерфейсе следует показывать системную ошибку, а не советовать слепое удаление приложения.
