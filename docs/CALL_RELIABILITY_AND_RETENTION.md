# Lumo: защита тестовых звонков и удаление служебных данных

**Статус:** черновик поверх PR #19 → #18 → #17 → #2. Продакшен не изменён. Реальные звонки всё ещё не проверены на двух устройствах, TURN пока не развёрнут.

## Что улучшено

- PostgreSQL advisory locks берутся **для обоих участников в одном порядке**. Одновременные вызовы A→Б и Б→A на разных экземплярах сервера не создают два приглашения и не образуют взаимную блокировку транзакций.
- Нельзя начать или получить второй звонок, пока один из участников уже занят действующим приглашением или принятым вызовом. API возвращает `409 call_busy`. По-прежнему действует серверное ограничение трёх **созданных запросов** в минуту для инициатора; дополнительные отклонённые попытки не создают звонки.
- Клиент Android больше не должен открывать микрофон после задержавшегося ответа TURN, если пользователь отменил подключение, завершил звонок или ушёл со страницы. Отдельный потокобезопасный счётчик поколений блокирует устаревшее создание WebRTC; `stop()` отменяет незавершённые задачи.
- Очередь исходящих SDP/ICE ограничена 64 элементами. При переполнении тестовая сессия останавливается вместо накопления памяти.
- Во время проверки сигналов разрешение микрофона повторно проверяется; при его отзыве сессия закрывается. Есть отдельная кнопка отмены подключения до запуска WebRTC.
- Когда активность Android перестаёт быть видимой (`ON_STOP`), тестовый аудиодвижок автоматически закрывается, даже если вкладка сохранилась в памяти. Повторное включение требует отдельного нажатия после возвращения.
- Для локальной проверки гонок добавлены JVM unit-тесты в Android CI. Существующий release-gate продолжает проверять отсутствие тестовых разрешений в собранном release manifest.

## Ротация и удаление служебных данных

Тестовая серверная сигнализация временно хранит SDP и ICE, которые могут содержать чувствительные сетевые метаданные. Очистка **не привязана к новым звонкам**: предусмотрен отдельный защищённый endpoint `GET /internal/call-cleanup`. Он удаляет сигналы старше одного часа и вызовы, срок жизни которых истёк более часа назад. На PostgreSQL добавлены индексы по времени для ускорения удаления.

**Оператор обязан настроить реальное расписание — сам код НЕ запускает cron.**

1. Только в изолированном staging: включить `LUMO_CALL_SIGNALING_ENABLED=true` и применить схему БД.
2. Настроить **секрет `CRON_SECRET` длиной минимум 32 байта** в защищённых переменных сервера. Не сообщать его в чате, репозитории или логах.
3. В поддерживаемом планировщике указать GET по HTTPS к `/internal/call-cleanup` с заголовком `Authorization: Bearer <CRON_SECRET>`. Для Vercel Cron на совместимом тарифе его можно связать с переменной `CRON_SECRET` и настроить на запуск не реже раза в час. Расписание/секреты не добавляются в этот PR автоматически.
4. Проверить `401` без секрета, `200` с тестовым секретом; протестировать повторные запросы и удаление искусственно состаренных строк без затрагивания активных вызовов.
5. До публичного выпуска дополнительно проверить логирование, резервные копии и фактический срок физического удаления данных: резервные копии PostgreSQL могут храниться дольше.

**Важно:** если периодический запрос не настроен или сервер недоступен, автоматического гарантированного удаления в течение часа нет. Истёкшие звонки недоступны через обычный API, но данные останутся в базе до успешной очистки. Ранее выданные временные TURN-учётные данные могут оставаться действительными до своей даты истечения даже после завершения звонка — одной только серверной проверки новых запросов недостаточно для немедленного отзыва этих данных.

## Критерии следующего этапа

После успешных Server/Android CI: установить изолированный TURN с TLS, настроить cron и проверить двустороннее аудио в разных сетях, отзыв разрешений, одновременные приглашения, отмену во время медленного получения TURN и закрытие микрофона при сворачивании/закрытии тестовой вкладки. До этого не сливать черновик в рабочую ветку и не распространять debug APK как обновление Lumo.
